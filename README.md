# world.execute(me); · HTML MV 生成资料包（v2）

本目录是一套“把《world.execute(me);》做成 standalone HTML MV”的后续使用材料。v2 的核心约定：

- **提示词不含歌词原文**，只含歌词节奏（129 行 start/end/section/emphasis）与音频分析。
- **音频改为外部单独提供**，但必须在最终成品中内联（base64 data URI）。
- **最终成品是一个 standalone HTML 文件**：CSS/JS/歌词（若提供）/音频全部内联，可离线双击运行。

## 1. 文件清单

| 文件 | 用途 | 是否含歌词原文 |
|---|---|---|
| FINAL_PROMPT.md | 最终完整提示词：节奏数据 + 音频分析 + 制作规范 | 否（只有节奏；曲名作为元数据保留） |
| README.md | 本说明：使用流程、输入协议、音频内联、验收清单 | 否（仅曲名，见 §3 说明） |
| lyric_timing_exam.json | 原始歌词与时序数据 | 是（text 字段）；作为生成时外部歌词来源，未内联进提示词 |
| audio_features_exam.json | 原始音频分析数据 | 否；已内联进提示词 |

工作区目前只有两个 JSON 素材，**没有音频文件**。音频需要你另行准备，并在生成时作为外部输入提供给模型。

## 3. 素材概况

- 曲目：Mili《world.execute(me);》，专辑 Miracle Milk，2016 年。
- 时长：211.9067 秒（3:31.907）；BPM 130（素材独立校验值 129.99，高置信度；被否决的 130.835 未采用）。
- 歌词节奏：129 行；49 行 emphasis；section 0–3（分别 12 / 74 / 42 / 1 行）。
- 节拍：459 个 beat、115 个 downbeat；首拍 0.344s、末拍 211.729s；周期 0.461538s。
- 音频分析：14 段 arrangement；129 条 perLineEnergy；424 条 0.5s energyCurve（覆盖 0–211.5s）；唯一静音窗 [207.467, 211.907]。
- 器乐窗（无歌词）：20–29.709 / 135.224–147.66 / 195.356–205.811 / 209.811–211.907 秒。
- 最后一行（i=128）在 205.811s 出现、209.811s 结束；其 end 落在静音段内，该 end 值不等同于“人声持续到 209.811s”（详见提示词 §10）。

**关于曲名**：提示词保留曲名作为作品标识；曲名恰好与某一句歌词相同，这是元数据层面的重叠。除曲名外，提示词不含任何歌词正文。

## 4. 使用流程（生成 standalone MV）

1. **准备音频**：自备与原曲对应的音频文件（建议与你后续播放/发布的版本一致）。没有音频就无法完成 v2 的成品。
2. **决定歌词模式**：
   - **有词版**：提供 129 行歌词文本（可直接提供 lyric_timing_exam.json，或只提供其中按 i 排列的 text）。提示词会要求逐字使用并内联进 HTML。
   - **无词版**：不提供歌词。提示词明确禁止模型显示、编造或使用记忆中的歌词，只用节奏/能量/结构做视觉。
3. **把三样东西交给模型**：FINAL_PROMPT.md + 音频文件 +（可选）歌词文本。
   - 建议使用**具备文件读写/脚本能力**的 agent / IDE 环境（例如 DSH、Claude Code、Codex 等）：因为需要把音频转成 base64 并写入 HTML。
   - 纯聊天窗口通常无法输出数 MB 的 base64；如果只能在聊天里做，模型应明确说明限制，而不是给你外链或假数据。
4. **保存产物**：模型应只产出一个 .html 文件，保存为 world-execute-me.html（或任意名字）。
5. **验收**：断网双击 Chrome 打开；DevTools → Network 应为 0 请求；音频能播放；按 §8 逐项检查。

## 5. 歌词：为什么不在提示词里

- 按本轮要求，FINAL_PROMPT.md 只保留节奏（i/start/end/section/emphasis），不含歌词原文；这样提示词本身可以独立分享/归档。
- 歌词原文仍在源文件 lyric_timing_exam.json 的 text 字段中。生成有词版时，把它作为外部输入提供给模型即可；不要把整段歌词再贴回提示词。
- 无词版：不提供歌词。提示词要求成品中任何位置（画面、隐藏 DOM、注释、aria-label、title、控制台）都不得出现歌词原文，也不得编造（曲名作为作品标识允许出现在 HTML title、片头与元数据中）。
- 无词版即使工作区里有含歌词的源 JSON，也不要把它作为歌词输入交给模型；提示词要求模型不读取、不引用未明确提供的歌词素材。
- 若外部歌词与节奏表行数/顺序不一致：提示词要求模型视为外部歌词不可用、改走无词模式并标“信息不足”，不得自行删行、补行、调序或拼接。

## 6. 音频：外部提供 → 成品内联

- 音频是必需输入；最终 HTML 中应有一个全局常量 AUDIO_DATA_URI，值为 data:audio/...;base64,...；播放器从它取源。
- 不得使用 http(s) 地址、相对路径或文件名；成品的 Network 面板必须 0 请求。
- 音频不要重新编码、裁剪、变速、变调或降质（除非你提供的本身就是最终版）；替换曲目/合成音频属于违规。
- base64 体积约为原文件的 4/3，成品 HTML 达到数 MB 属正常；不能因为体积大就外链或删减音频。
- 浏览器通常禁止无手势自动播放带声音的音频；成品需要可点击的播放/开始入口，点击后音频与时间轴一起走。
- 音频版本要与素材分析版本一致；否则行时间戳会偏移，需要重新对齐（本资料包没有音频版本信息，属于信息不足）。
- 生成环境建议用脚本完成编码与写入，不要把几 MB 的 base64 手工复制到对话里。

## 7. 信息不足清单（素材层面）

| # | 缺什么 | 影响 | 处理建议 |
|---|---|---|---|
| 1 | 音频文件（工作区没有） | 无法完成“内联音频的 standalone 成品” | 生成前自行提供音频 |
| 2 | 歌词原文（按设计不在提示词中） | 有词版需外部提供文本；无词版不能显示歌词 | 按有词/无词模式准备输入 |
| 3 | 逐字、逐音素、音高与演唱时刻 | 不能做真正的逐字卡点 | 行内节奏只从行时长、文本长度、emphasis、节拍、能量推断 |
| 4 | onset 事件列表；onsetDensity 的单位 | 不能精确刻画起音密度 | 只作相对比较 |
| 5 | 人声/伴奏分离、和声、调性、和弦 | 不能做和声/调性驱动的视觉 | 不要编造 |
| 6 | arrangement 标签的生成方法、section 编号语义 | 不能把标签当曲式定义或事实 | 只当分段/分组 id |
| 7 | 音频分析参数（窗长、归一化、频段划分） | 能量数值不能当绝对测量值 | 只做相对趋势 |
| 8 | 官方 MV、创作背景、乐评等外部资料 | 任务禁止引用 | 不引用、不假装知道 |
| 9 | 音频版本/对齐信息 | 换版本会偏移时间戳 | 使用与分析一致的版本，或重新对齐 |
| 10 | 歌词/录音授权状态 | 素材未给出授权说明 | 公开发布前自行确认权利 |

## 8. 成品验收清单（人工）

- [ ] 最终只有一个 .html 文件；无单独音频/图片/字体/JS/CSS 文件；无外部依赖。
- [ ] 音频以 data URI 内联；AUDIO_DATA_URI 非空且能解码；离线播放正常；Network 面板 0 请求。
- [ ] 播放由用户点击启动；音频与画面同步；结束后有明确结束状态且可重播。
- [ ] 有词版（校验通过时）：129 行全部出现、逐字一致、顺序与 i 一致；start 前不可见、end 后不再作为当前行；无翻译/补写/改写。
- [ ] 无词版：除曲名元数据外，成品任何位置（画面/DOM/注释/aria-label/console）都没有歌词原文，也没有模型记忆中的歌词。
- [ ] 129 个 start/end 未被平移、缩放或取整到 0.1s。
- [ ] 器乐窗内没有歌词：20–29.709、135.224–147.66、195.356–205.811、209.811–211.907。
- [ ] 行内节奏只基于允许的数据；没有伪造逐字时间、波形、频谱或人声分析。
- [ ] 视觉全部由代码生成，无外部图片、视频、字体、音效、乐评或参考资料。
- [ ] 使用 130 BPM 网格（t0=0.344、period=0.461538）时没有擅自“修正”数据。
- [ ] 控制台无未捕获错误；窗口缩放不重置时间轴；观感流畅。
- [ ] 信息不足清单存在；音频/歌词缺失情况如实标注。
- [ ] 存在导演手记、冲突方案比较与选择理由。
- [ ] 文件大小合理（通常为几 MB 到十几 MB，取决于音频）。

## 9. 常见失败模式

1. **无词版却出现歌词**：模型凭记忆补词、从网络找词、或把源文件歌词又塞回成品。→ 必须删除，提示词已禁止。
2. **有词版歌词被改写或漏行**：→ 对照外部提供的 129 行文本逐行核对。
3. **音频外链**：出现 http(s) 音频地址或相对路径。→ 必须改为 data URI 内联。
4. **假内联**：AUDIO_DATA_URI 为空、假 base64、截断数据。→ 检查文件大小与播放是否正常。
5. **两个文件**：HTML + 单独音频。→ 不合格，必须合并为一个 standalone HTML。
6. **时间戳被平移/取整/重排**：→ 对照提示词 §2 节奏表原值。
7. **把 section 当曲式名或编造背景**：→ 数据未定义，删除断言或标“信息不足”。
8. **无播放入口/自动播放失败**：→ 必须有用户手势启动的播放入口。
9. **纯聊天环境硬交差**：输出数 MB base64 不现实，模型应说明限制；建议改用有文件/脚本能力的 agent。
10. **把歌词贴回提示词**：破坏“提示词可独立分享”的设计；歌词只作为外部输入。
