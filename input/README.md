# INPUT — 音频与歌词的放置协议

本仓库不含音频字节与歌词原文。使用者在**仓库根目录**放入音频与歌词即可；**文件名、格式不限**，生成时会自动识别。**音频与歌词都是必需输入。**

## 放置位置与识别

| 输入 | 位置 | 可接受的格式 |
|---|---|---|
| 音频 | 仓库根目录（或一层子目录，或对话中给出的路径/附件） | mp3 / m4a / aac / wav / flac / ogg / opus / webm / aiff / aif / wma / alac / m4b / mka / mp4 等；任意文件名 |
| 歌词 | 同上 | txt / text / lrc / srt / ass / vtt / md / json 等文本类；任意文件名 |

- **不需要改名，也不需要转格式**；AI 会按扩展名与文件头识别，必要时读取内容判断。
- 根目录自带 `audio.mp3.example`、`lyrics.txt.example` 两个占位说明文件（不是输入），放好真实文件后可删除。
- 多个同样合理的候选同时存在时，AI 只会问一次让你选；否则不会打扰。

## 音频

- **读取**：从识别到的路径读取。最终必须**原样**内联进 HTML（契约见 [CONTRACT.md](../CONTRACT.md) §5）：`data:audio/...;base64,...`。不得转码、裁剪、变速、变调。
- **编码**：任何工具/语言都可以（也可直接用模型的文件读取与编码能力）。base64 约为原文件 4/3，成品数 MB 属正常；上限见 [delivery/FORMAT.md](../delivery/FORMAT.md)。
- **不可用**（缺失/损坏/无法内联）：标记"未完成：音频未内联"，不得假内联、外链或改用替代曲（[CONTRACT.md](../CONTRACT.md) §4 第 9 条、§5）。
- **版本/对齐**：未说明版本一致时不得假定完全对齐；发现整体偏移按信息不足处理，不得改时间戳（[CONTRACT.md](../CONTRACT.md) §1）。

## 歌词

- **必需**：任意文件名/文本格式；清洗后（去掉时间码、编号、标题、空行、注释）应为 129 行，按 `i=0–128` 对应 [data/lyrics_timing.json](../data/lyrics_timing.json) 的 `lines`。
- **带时间码的格式**（LRC / SRT / VTT / ASS）：先去时间码与元数据，只保留歌词文本。
- **来源限制**：只能来自使用者的外部提供；禁止模型记忆中的歌词、网络搜索、官方 MV 字幕、其他翻唱版本。
- **校验**：清洗后行数 = 129 且顺序可对应。通过后按逐字锁定使用（锁定规则见 [CONTRACT.md](../CONTRACT.md) §1）。
- **降级路径**：清洗后仍不等于 129 行 → **视为外部歌词不可用，改走无词模式**（成品不显示任何歌词），并在交付说明中标注"信息不足"；不得自行删行、补行、调序，也不得从其他版本拼接。降级不是默认形态。
- **无词模式下的取材限制**：即使工作区/附件存在含歌词文本的素材文件，也不得读取、引用或显示其中的歌词；只有使用者明确指定为"歌词输入"的内容才可使用。
- **无词模式下的显示限制**：成品中不得出现任何歌词原文（画面、隐藏 DOM、注释、aria-label、HTML title、控制台日志等），也不得用相近文本替代。**例外：曲名 world.execute(me); 作为作品标识，允许出现在 HTML title、片头、元数据与 `data/*.json` 的 `meta.title` 中；不得据此扩展显示/编造其他歌词。**

## 防误提交

- 真实音频与歌词只留本地；`.gitignore` 已覆盖常见音频与歌词扩展名，AI 还会把识别到的输入路径追加到 `.git/info/exclude`（本机忽略，不会提交）。

## 数据文件

`data/*.json` 随仓库提供、只读；不通过 input 提供，也不需要使用者替换（详见 [data/DATA_NOTES.md](../data/DATA_NOTES.md)）。
