# INPUT — 音频与歌词的放置协议

本仓库不含音频字节与歌词原文。使用者在**仓库根目录**放置两份文件，生成时从根目录读取；**音频与歌词都是必需输入。**

## 放置位置

| 文件 | 路径 | 格式 |
|---|---|---|
| 音频 | `./audio.*`（如 `audio.mp3`、`audio.m4a`、`audio.wav`、`audio.flac`） | 原始音频文件，不转码 |
| 歌词 | `./lyrics.txt` | UTF-8 纯文本，恰好 129 行，每行对应 i=0–128 |

## 音频

- **读取**：从仓库根目录读 `audio.*`。最终必须**原样**内联进 HTML（契约见 [CONTRACT.md](../CONTRACT.md) §5）：`data:audio/...;base64,...`。
- **编码**：可以用 PowerShell 的 `[Convert]::ToBase64String([IO.File]::ReadAllBytes("audio.mp3"))`，或 macOS/Linux 的 `base64 -w0 audio.mp3`；也可以直接用模型的文件读取与编码能力。
- **体积**：base64 约为原文件 4/3，成品数 MB 属正常；不得因体积删减音频或改外链（上限见 [delivery/FORMAT.md](../delivery/FORMAT.md)）。
- **不可用**（缺失/损坏/无法内联）：标记"未完成：音频未内联"，不得假内联、外链或改用替代曲（[CONTRACT.md](../CONTRACT.md) §4 第 9 条、§5）。
- **版本/对齐**：未说明版本一致时不得假定完全对齐；发现整体偏移按信息不足处理，不得改时间戳（[CONTRACT.md](../CONTRACT.md) §1）。

## 歌词

- **必需**：`./lyrics.txt`，129 行，按 `i=0–128` 对应 [data/lyrics_timing.json](../data/lyrics_timing.json) 的 `lines`。
- **格式**：UTF-8 纯文本，一行一句；不要时间戳、编号、标题、空行或注释。
- **来源限制**：只能来自使用者的外部提供；禁止模型记忆中的歌词、网络搜索、官方 MV 字幕、其他翻唱版本。
- **校验**：行数 = 129 且顺序可对应。校验通过后按逐字锁定使用（锁定规则见 [CONTRACT.md](../CONTRACT.md) §1）。
- **降级路径**：行数或顺序不符 → **视为外部歌词不可用，改走无词模式**（成品不显示任何歌词），并在交付说明中标注"信息不足"；不得自行删行、补行、调序，也不得从其他版本拼接。降级不是默认形态。
- **无词模式下的取材限制**：即使工作区/附件存在含歌词文本的素材文件，也不得读取、引用或显示其中的歌词；只有使用者明确指定为"歌词输入"的内容才可使用。
- **无词模式下的显示限制**：成品中不得出现任何歌词原文（画面、隐藏 DOM、注释、aria-label、HTML title、控制台日志等），也不得用相近文本替代。**例外：曲名 world.execute(me); 作为作品标识，允许出现在 HTML title、片头、元数据与 `data/*.json` 的 `meta.title` 中；不得据此扩展显示/编造其他歌词。**

## 数据文件

`data/*.json` 随仓库提供、只读；不通过 input 提供，也不需要使用者替换（详见 [data/DATA_NOTES.md](../data/DATA_NOTES.md)）。
